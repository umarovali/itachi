# Itachi Store

Сайт пополнения игр. Товары выполняет Donix (партнёрский API), оплату покупатель переводит через свой банк (ссылка payqr.kg)
(O!Bank / Элкарт, всегда в сомах), админ подтверждает оплату кнопкой в Telegram-боте.

```
web/     сайт (React + TypeScript + Vite)
admin/   админка (React + TypeScript + Vite), адрес /admin/
server/  сервер (Node.js + TypeScript, SQLite): Donix, вебхуки, курсы, Telegram-бот, вход в админку
```

## Запуск

Нужен Node.js 23.6 или новее.

```bash
npm run install:all          # один раз
cp server/.env.example server/.env   # один раз, потом заполнить
npm run dev                  # сервер (3000) + сайт (http://localhost:5173) + админка (http://localhost:5174/admin/)
```

## Настройка `server/.env`

| Что | Где взять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather → /newbot |
| `DONIX_API_KEY` | кабинет Donix → «Настройки API» → «Создать API-ключ». Пока пусто — Donix в **тестовом режиме** |
| `DONIX_WEBHOOK_SECRET` | там же, секрет вебхука |
| `DONIX_BASE_URL` | сверьте с документацией Donix (по умолчанию `https://back.donix.org/api/partner/v1`) |
| `MARKUP_PERCENT` | ваша наценка, % (меняется и в боте: `/markup 12`) |

После изменения `.env` сервер нужно перезапустить.

## Админы

- **Суперадмин — всегда один.** При первом запуске сервер печатает в консоль `/claim КОД` — отправьте это боту.
- Суперадмин добавляет админов: человек пишет боту `/start` → суперадмину приходит кнопка «➕ Сделать админом»
  (или `/addadmin ID имя`, `/deladmin ID`, `/admins`).
- **Вход в админку** — без пароля: «Войти через Telegram» → бот спрашивает «Подтвердить вход?» → «✅ Да, это я».
  Сессия живёт 7 дней. Удалённый админ теряет доступ сразу.

## Как проходит заказ

1. Покупатель выбирает пакет, вводит ID → сервер проверяет его через Donix `/validate`.
2. Сервер считает цену: `цена Donix ($) × (1 + наценка) × курс сома`, это и есть сумма к оплате.
   30 минут на оплату. Перевод находим по чеку и имени отправителя.
3. Покупатель переводит, **прикрепляет чек (скриншот или PDF)**, пишет имя отправителя, жмёт «Я оплатил» →
   бот присылает чек и карточку с кнопками ✅ / ❌ (то же самое — в админке). Чеки лежат в `server/data/receipts/`
   и доступны только админам.
4. ✅ → заказ уходит в Donix → вебхук `completed` → покупатель видит «Готово» на сайте (`/order/КОД`).
5. Ошибка Donix (нет баланса, failed, refunded) → тревога в боте, кнопки «Повторить» / «Вернул деньги».

## Тестовый режим Donix

Пока нет `DONIX_API_KEY`: тестовый каталог, тестовый баланс 50 $, заказы «выполняются» через 5 секунд.
UID, оканчивающийся на `0`, имитирует ошибку Donix (`failed`).

## Подключение настоящего Donix — проверить по документации в кабинете

Формат запросов взят с публичной страницы donix.org/api, в ней нет всех деталей. Когда будет доступ:

- базовый адрес API → `DONIX_BASE_URL`;
- поля запроса `/validate` и `/order` (сейчас отправляем `sku`, `uid`, `server`/`zone`, `external_id`) —
  `server/src/donix.ts`;
- как называются SKU игр в `/products` — префиксы в `server/src/games.ts`;
- адрес вебхука для кабинета: `https://ВАШ-ДОМЕН/api/webhooks/donix` (работает только на сервере с доменом, не локально).

## Деплой на Render

Один Web Service: сервер отдаёт и API, и собранный сайт (`/`), и админку (`/admin/`). Настройки — в `render.yaml`.

1. Залить репозиторий на GitHub (файл `server/.env` и папка `server/data/` в git не попадают).
2. Render → **New → Blueprint** → выбрать репозиторий → Render прочитает `render.yaml`.
3. Заполнить секреты: `PUBLIC_SITE_URL` (`https://<имя>.onrender.com` или свой домен), `TELEGRAM_BOT_TOKEN`,
   `DONIX_API_KEY`, `DONIX_WEBHOOK_SECRET`.
4. После первого запуска: **Logs** → найти `/claim КОД` → отправить боту.
5. В кабинете Donix указать вебхук `https://<домен>/api/webhooks/donix`.

Нужен платный план (Starter): бесплатный засыпает через 15 минут (бот перестаёт отвечать) и не даёт диск —
база и чеки стирались бы при каждом деплое. База и чеки лежат на диске `/var/data`.
Локальную базу можно перенести: Render → Shell → загрузить `itachi.db` в `/var/data/`.
